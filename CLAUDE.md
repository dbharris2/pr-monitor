# PR Monitor

A personal GitHub PR dashboard with two surfaces: a Next.js web app and a Chrome extension. Both render the same React UI from a shared package.

## Layout

This is a bun-workspaces monorepo. All source lives under `packages/`:

- **`packages/ui`** — shared React components, utils, Relay fragments, GraphQL schema, Tailwind preset. Consumed by both apps.
- **`packages/www`** — the Next.js app. Deployed to Vercel.
- **`packages/extension`** — the Chrome extension (MV3 popup + service worker).

Each package has its own `CLAUDE.md` with package-specific notes.

## Conventions

- **Singleton runtime libs are peer deps in `ui`.** `react`, `react-dom`, `react-relay`, `relay-runtime`, `graphql` — multiple copies cause silent context bugs.
- **Path aliases (`components/*`, `utils/*`)** are kept in each consuming package's tsconfig pointing at `../ui/...`, so import statements never include `@pr-monitor/ui/...`.
- **Relay artifacts (`packages/ui/components/__generated__/`) are not checked in.** They're regenerated by `prebuild` scripts in `www` and `extension` before each build. After `git clone`, run `bun relay` once before `bun ts` / `bun lint` work.
- **Each package owns its full toolchain.** No shared base ESLint / Tailwind / Prettier config; every package has its own. Intentional — keeps each one debuggable in isolation. Root `package.json` is just `workspaces` + script proxies.
- **Auth differs by surface.** The web app encrypts the token in an HTTP-only cookie and proxies GitHub calls server-side. The extension stores the token in `chrome.storage.local` and calls `api.github.com` directly (`host_permissions` in the manifest allows it).
- **The `Header` component takes `saveToken` as a prop** so it works in both surfaces without a hard dep on the Next server action.

## Common scripts (root)

```bash
bun dev         # Web dev server on :3001
bun build       # Production build of the web app
bun ext:dev     # Vite dev server for the extension
bun ext:build   # Production build of the extension (output: packages/extension/dist/)
bun relay       # Regenerate Relay artifacts after editing GraphQL
bun ts          # TypeScript check across all packages
bun lint        # ESLint across all packages
bun format      # Prettier across all packages
```

All proxy to the relevant workspace via `bun --filter`.

## Tech stack

- Next.js 16 (Turbopack) + React 19 (React Compiler) for the web
- Vite + `@crxjs/vite-plugin` + `@rolldown/plugin-babel` (running `babel-plugin-relay`) for the extension
- Relay 21
- Tailwind CSS + Catppuccin
- TypeScript 6
