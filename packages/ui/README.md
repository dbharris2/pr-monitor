# @pr-monitor/ui

The shared component library and schema for PR Monitor. Both [`@pr-monitor/www`](../www) and [`@pr-monitor/extension`](../extension) consume this package.

## Layout

- `components/` — React components, each colocated with its Relay fragment.
- `components/__generated__/` — Relay-compiler output. Not checked in; regenerated by `bun run relay`.
- `data/schema.graphql` — GitHub's GraphQL schema, used by the Relay compiler. Refresh by re-downloading from GitHub.
- `utils/` — small browser-safe helpers (`cn`, `nonnull`, `useLocalState`, etc.).
- `tailwind-preset.ts` — the Catppuccin color palette + custom variants. Both consuming apps' `tailwind.config.ts` import it via `presets: [preset]`.
- `relay.config.json` — Relay-compiler config. `src` and `schema` are relative to this file.

## Scripts

```bash
bun run lint    # ESLint for this package only
bun run ts      # TypeScript check for this package only
bun run relay   # Run relay-compiler — regenerates components/__generated__/*
bun run format  # Prettier
```

## Adding a new component

1. Create the file under `components/`.
2. If it has a `graphql` tagged template, run `bun run relay` (or `bun relay` from the root) to generate the type artifacts.
3. Import it from the consuming app using the `components/*` tsconfig path alias — e.g. `import { Foo } from 'components/foo'` from `www` or `extension`.

## Dependencies

Singleton runtime libraries (`react`, `react-dom`, `react-relay`, `relay-runtime`, `graphql`) are declared as `peerDependencies` so they resolve to a single instance in the consuming app — multiple `react-relay` copies would mean fragment reads from this package couldn't see providers mounted in the consumer.
